# Visual Companion

Throwaway browser visuals for brainstorming. Read this only after the user accepts the offer.

## When It Earns Its Cost

- Spatial or layout questions — where things go on a screen
- Comparing 2-3 approaches side by side
- State diagrams or flows the user must react to

## When It Doesn't

Anything you can convey precisely in two sentences. If words suffice, use words — a visual is a cost, not a flourish.

## How

1. Build one self-contained HTML page: inline CSS/JS, no external assets, no build step.
2. Open it in a browser, or hand the user the path.
3. Keep it to one screen. If it needs scrolling, it is becoming a deliverable in disguise — cut scope.

## Rules

- Visuals are communication aids, never deliverables. No polish, no pixel-perfection, no keeping them.
- Every decision made while looking at a visual gets written back into the design text immediately. The design doc is the source of truth; the mockup is scratch paper.
- Never iterate more than twice on one visual. If it needs a third round, the question is wrong, not the mockup — step back and reframe what you are actually asking.

## Cleanup

Delete the HTML once the question is resolved. Nothing visual enters the repo unless the user explicitly asks.
