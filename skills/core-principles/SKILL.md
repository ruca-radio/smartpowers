# Core Principles

## Test-Driven Development

Write the test first. Watch it fail. Write minimal code to pass. If you didn't watch it fail, you don't know if it tests the right thing.

## Systematic over Ad-hoc

Process prevents thrashing. A methodical approach is faster than guess-and-check under pressure.

## Complexity Reduction

Simplicity is the primary goal. YAGNI ruthlessly. Break systems into units with one clear purpose, well-defined interfaces, and no hidden coupling.

## Evidence over Claims

Verify before declaring success. A test passing proves the behavior. A manual check does not.

## DRY Applies to Instructions

Say it once, reference it everywhere. Shared patterns live in `discipline-template`, not repeated across skills.

## Violating the Letter Is Violating the Spirit

Rules exist because agents rationalize around them. Follow the specific instruction, not the imagined intent.
